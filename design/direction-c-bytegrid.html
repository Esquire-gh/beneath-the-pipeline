part ii — the pipeline, one line at a time

04 · load — from disk to memory

loader.load(), finally cashed out. The first line of the Part 0 pipeline and the last one anybody looks at.

symptom

You have 10,000 small files. You have one large file holding the same total bytes. Reading the 10,000 takes far longer than reading the one.

Same bytes off the same disk. Where did the extra time go?

build

Open exercises/04-load/starter.py. The plumbing is written; three TODOs are not. You will read the same corpus three ways — file by file, line by line, and one large buffered read — and count how many times each one crosses into the operating system.

Every one of those open() and read() calls is a syscall: a function call with a border crossing inside it. Your program cannot touch the disk. It asks the operating system to, and the ask costs something even when the answer is already sitting in memory.

observe

Don't look at the absolute times; your machine is not this machine. Look at the ratio, and look at the crossings column next to it.

explain

Loading is four things, and none of them is magic. Consult the bookkeeping the operating system keeps about your bytes — the record from module 1 — to find which blocks belong to this file. Ask for those blocks in as few crossings as you can. Decode the bytes by whatever convention was agreed on, which is module 2. Hold the result in memory.

connect

Upward: loader.load() is that list, in that order, with the crossing count hidden from you. Backward: module 1 said a file is a row of blocks and a record pointing at them. This module is what it costs to actually go get them.

meaning is a convention; arrangement is a cost.

read & check

Petrov, Database Internals, Part I. Read it for one thing: how storage engines batch their work specifically to stay off the boundary you just measured.

  1. Your corpus is 300 MB. Why did reading it file-by-file cost more than reading it in one call, when the disk moved the same bytes?
  2. What does a buffer size of 64 KB buy you over 4 KB, and where does that stop paying?
  3. Which of the three strategies would you use on a corpus larger than your RAM, and what breaks first?
